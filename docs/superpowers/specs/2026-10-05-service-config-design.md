# Конфиг сервиса в openspec/config.yaml

Машина читает настройки сервиса из `openspec/config.yaml` в корне, откуда запущен `sdd`. Очередь, база, префикс ветки и список игнорируемых авторов живут там. `sandcastle.yaml` машина не читает и `sdd-init` его не создаёт. Каталог `.sandcastle/` (checkout, ссылки, логи, `.env`) остаётся.

## Файл

Путь: `<корень сервиса>/openspec/config.yaml`. Корень — каталог процесса `sdd`, аргумент `openMachine` и `createAdapters`. Каталог скила и каталог пакета этот файл не держат.

CLI OpenSpec 1.14.0 разбирает в этом файле только `schema`, `context` и `rules`. Ключ `sdd` он пропускает, `openspec validate` из‑за него не падает.

```yaml
schema: spec-driven
context: |
  ...
sdd:
  base: trunk
  branch-scope: sdd
  ignore-comments:
    - dependabot
  queues:
    - name: LAVKAOPSCORE
      description: Обычные задачи этого сервиса
```

`base`, `branch-scope` и `ignore-comments` можно не писать. `queues` обязателен: список не пустой, у каждого элемента есть `name`. `description` можно не писать.

Нет файла, нет ключа `sdd`, нет `queues`, пустой список или элемент без `name` — команда останавливается и называет, чего не хватает.

## Умолчания

Их подставляет один разбор, `loadServiceConfig(serviceRoot)`:

| Поле файла | Нет поля | Смысл |
|---|---|---|
| `base` | `trunk` | Имя ветки. Пул-реквест открывается в неё. Git режет ветку тикета от `origin/<base>`, arc — от `<base>`. |
| `branch-scope` | `sdd` | Префикс. Ветка тикета — `<prefix>/<ключ>`. |
| `ignore-comments` | пустой список | Шаблоны логинов. Регистр не важен, строка становится регулярным выражением. Кривой шаблон останавливает команду и называет ключ `ignore-comments`. |
| `queues` | остановка | Имени очереди по умолчанию нет. |
| `queues[].description` | поле отсутствует | Машине достаточно имени. |

Уже лежащий в сервисе `sandcastle.yaml` машина не открывает и не удаляет.

## Кто потребляет

`openMachine` вызывает `loadServiceConfig` до портов и до `createAdapters`. Адаптер получает этот конфиг и не подменяет очереди, базу и префикс своими константами. Жёстких `LAVKAOPSCORE` и `trunk` в `adapters/index.mjs` нет.

В машине поля называются `queues`, `base`, `branchScope`, `ignoreComments`. `queues` — список `{name, description?}`. Первая очередь — место для нового подтикета. `decide` и `settle` описания не разбирают.

Тикет входит в цикл, когда на нём есть `sdd:cycle` и имя одной из очередей. Трекер ищет каждую очередь отдельно и добавляет её имя к меткам тикета. На GitHub имя очереди — метка тикета. Два имени на одном тикете: побеждает то, что раньше в файле. В JSON решения `queue` — имя очереди этого тикета, `base` — база сервиса.

`ignoreComments` приходит в порты ревью из собранного конфига. Отдельного разбора `sandcastle.yaml` в пакете и в адаптере Аркадии нет.

## sdd-init

Этап OpenSpec по-прежнему создаёт `openspec/config.yaml` через `openspec init`. Этап машины спрашивает очереди (имя обязательно, описание по желанию) и ботов и дописывает ключ `sdd`. `schema`, `context` и `rules` остаются. Нет имени очереди — этап останавливается, файл без `queues` не пишется. `sandcastle.yaml` этап не создаёт и путь к адаптерам никуда не пишет.

## Проверка

- Разбор подставляет `trunk`, `sdd` и пустой список авторов, когда этих ключей нет.
- Нет файла, нет `sdd`, нет `queues` или нет `name` — ошибка называет недостающее.
- `description` можно опустить.
- Кривой шаблон в `ignore-comments` называет этот ключ.
- Цикл из двух очередей берёт тикеты обеих. Две метки очереди на одном тикете дают ту, что раньше в файле.
- `createAdapters` не возвращает свою очередь и базу.
- `openspec validate` принимает файл с ключом `sdd`.
