## Problem

Render sidebar documents as markdown.

Plan, Specify, Design, and Tasks render their markdown in the sidebar: headings, lists, emphasis, links, and code. Each source line stays a comment target, and a click still opens the remark draft on that line. A diff row keeps its add and delete coloring and its comment control. The focus block renders its prose the same way and does not treat the marker line as a heading.

The line anchors and the diff grid are the leaves of that render. A reload shows the same comments on the same lines.

This issue files the child cycles that land that render. It does not land the render itself. A proposal for this issue names no capability. The caller-visible rule arrives on a child.

## Outcome

File the children from that study. This issue does not name their titles. The order of the surfaces is fixed. The cut inside a wave is the study's.

2. Specify, after that wave is accepted.
3. The remaining surfaces, after Specify is accepted. Tasks and the focus block are the ones this issue already knows. The study names any other.

The study may show that those sections cannot share an engine until a platform is in place, or until the render architecture is refactored. File that child first when a later child would otherwise build a second engine, or would cut across a seam that should move first. Say which later children it unblocks. Leave it unfiled when the study does not need it.
