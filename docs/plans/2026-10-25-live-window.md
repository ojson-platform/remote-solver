# Живое окно

Семь наблюдений на фазе specifying. Чинить их по фазе нельзя: те же механизмы рисуют Plan, Design и остальные станции.

План идёт сверху вниз. Следующая задача начинается, когда предыдущая зелёная. React — задачи 5–7, после того как модель окна уже говорит правду.

## Корни

**Документ рисуется один раз.** `page.ts` отдаёт целый HTML на `GET /` и на `303` после `POST`. Скрипт в странице не перечитывает её. Сервер каждые 15 секунд и после опроса шпиона обновляет свой кэш тикетов (`REFRESH_MS`, `onCycle`), но открытая вкладка об этом не узнаёт. Сценарий «The page reads the tracker again while it stays open» считает вызовы `listOpen`, не перерисовку вкладки. Поэтому «Принять» в Plan пишет `sdd:proposed`, шпион позже переводит цикл в `specifying`, а на экране остаётся прежний документ, пока его не перезагрузят.

**Шапка — последняя строка журнала шпиона, не текущий ход.** `cli.ts` кладёт в шапку каждый `onReport`. `runSpy` пишет туда `#6 start specifying → restore-baseline` в момент старта воркера. `driveIssue` может внутри того же воркера пройти `restore-baseline`, затем `create-initial-specs`, и эти ходы пишет только в `console.log`. Строка в шапке не меняется, пока воркер не выйдет (`#6 worker exited 0`) — и то новая строка попадёт на экран только со следующей загрузкой. Лампа «шаги идут» означает, что конфиг фабрики может начать шаг, а не что агент сейчас работает.

**Пустая плашка — следствие двух правил, не дыра только у specifying.** У `specifying` и `tasking` нет фазовой строки. Пока агент ведёт шаг, `hideIcon` выкидывает и значок, и текст причины. Спека доски говорит другое: текст плашки остаётся, отдельная отметка повода не добавляется. Когда причины нет, сверху и снизу пусто, и `plaque` рисует `&nbsp;`.

**«Принять» у Specify не ждёт дельту.** `reviewReady` для `proposed` требует proposal без открытых вопросов, для `designed` — design без открытых решений, для `specified` возвращает `true`. Кнопка встаёт сразу, как только плашка на `specifying` и pull request один. Машина при `sdd:specified` без дельты возвращает цикл назад (`review-gate`). Окно предлагает жест раньше, чем артефакт есть. Тест `Accepting the spec adds specified` как раз ждёт кнопку без файла спеки.

**«Принято» — квитанция POST, которая живёт в памяти процесса.** `acceptReview` возвращает `'Принято.'`, `apply` кладёт это в `view.status`, документ рисует `<p class="status">` между шапкой и доской. Поле не сбрасывается. Следующие `GET` повторяют ту же строку. Успех принятия — это метка `sdd:proposed` / `sdd:specified` / `sdd:designed`, не плашка над доской.

**Лог агента не готов к показу как есть.** Файлы `.sandcastle/logs/sdd-6-*.log` — JSONL потока Cursor. `runProcess` дописывает файл и не обрезает прошлый запуск того же действия.

| лог | размер | длительность | thinking | реплики | tool result |
| --- | --- | --- | --- | --- | --- |
| `sdd-6-create-proposal.log` | 1.2 МБ | 458 с | 1004 дельты, 39 КБ | 1.6 КБ | 888 КБ |
| `sdd-6-restore-baseline.log` | 1.0 МБ | 680 с | 3467 дельт, 87 КБ | 1.6 КБ | 349 КБ |
| `sdd-6-create-initial-specs.log` | 570 КБ | 390 с | 1659 дельт, 44 КБ | 1.1 КБ | 209 КБ |

Тяжёлое — не текст агента, а результаты инструментов: `glob` всего worktree (200 КБ), `grep` по минифицированному `sdd.mjs`, чтение `src/window` и даже `openspec/dist` из глобального `node_modules`. Глаголы harness уже записаны в `skills/sdd-flow/CONTEXT.md` (`publish`, `mirror`, `thread`, `threads`, `worktree`, `wait`). Промпт велит прочитать этот файл и не выбирает глаголы сам. Агент всё равно ищет их в бандле. В `create-proposal` два `system:init`: второй запуск дописан в тот же файл.

Попап с сырым JSONL будет стеной thinking-дельт. Показывать надо проекцию: реплика, имя инструмента и короткий аргумент, ошибка. Thinking не показывать.

## Как устроено живое окно

Строковый рендерер и React одновременно не живут. Пока React не покрывает шапку, доску, сайдбар и настройки, страница остаётся той, что есть. Поведение задач 1–4 входит в эту страницу и в снимок, с которого React потом рисует. Отдельный опрос `location.reload` не делаем: он сбрасывает открытый ряд спины и черновики строк.

Снимок — чистая функция от surface и `PageView`. В нём поколение, лампа, текущий ход, ряды доски, открытый цикл, spine, настройки. Эфемерное остаётся в клиенте: какой ряд спины открыл человек, черновик строки, открыт ли попап лога. Когда станция плашки меняется, открытый ряд спины становится слоем этой станции. Пока станция та же, выбор человека не сбрасывается.

Канал:

- `GET /snapshot` — JSON снимка.
- `GET /events` — SSE, событие `change` с номером поколения, когда сменился ход, кэш тикетов или `POST`.
- `POST /act` и `POST /take` отвечают `200` и телом снимка, когда клиент — React. До переключения остаётся `303`.

Клиент на событие забирает снимок. GitHub он не опрашивает: сервер и так читает трекер раз в 15 секунд и после цикла шпиона.

Каталог клиента, когда дойдём до задачи 6:

| файл | ответственность |
| --- | --- |
| `src/window/snapshot.ts` | снимок, без HTML |
| `src/window/client/main.tsx` | корень, подписка, черновики |
| `src/window/client/Header.tsx` | лампа и ход |
| `src/window/client/Board.tsx` | плитки, плашки, двери |
| `src/window/client/Sidebar.tsx` | спина, «Принять», ворота |
| `src/window/client/Settings.tsx` | лист настроек |
| `src/window/client/Log.tsx` | попап проекции лога |
| `src/window/face.css` | нынешние цвета и размеры, без новой темы |

Имена из `src/window/CONTEXT.md` сохраняются: Face, Card, Pill, Circle, Field. Компонент не называется Button и Panel.

Сборка: `react` и `react-dom`, JSX в `tsconfig`, бандл esbuild при старте `board` (esbuild уже в devDependencies). В репозиторий бандл не кладём. Тесты снимка остаются на `node:assert`. Видимые сценарии на переключении рендерит `react-dom/server`. `page.test.ts` живёт, пока строковый документ — то, что отдаёт сервер, и удаляется в задаче 6 вместе с ним.

Попап лога читает `GET /logs/:issue`. Сервер берёт путь через `agentLogPath`, проецирует хвост после последнего `system:init` и отдаёт последние 80 строк проекции. Пока попап открыт, клиент перечитывает этот путь раз в секунду. В снимок доски лог не входит.

## Задачи

### Задача 1. Шапка называет текущий ход

- [x] Ход — `{issue, phase, action} | undefined`, не сырая строка журнала.
- [x] `driveIssue` сообщает ход на каждой итерации и снимает его, когда решение уже не agent.
- [x] `runSpy` снимает ход, когда воркер вышел. `worker exited` остаётся в stdout.
- [x] Страница показывает `#<issue> <phase> → <action>`, пока ход есть, и ничего, когда хода нет.
- [x] Спека `board`: требование про команду board и два сценария — старт хода и смена хода с уходом строки.
- [x] Открытая вкладка всё ещё показывает прежний документ, пока не будет задачи 6. Обновление страницы уже показывает новый ход, а не первый `start`.
- [x] Ход без коммита помечает простой сигнатурой этого хода, а не хода, с которого воркер стартовал. Иначе следующий опрос сразу поднимает `restore-baseline` снова.

Файлы: `src/main.ts`, `src/window/live.ts`, `src/cli.ts`, `src/window/live.test.ts`, `openspec/specs/board/spec.md`, `openspec/specs/idle/spec.md`.

### Задача 2. Пустая плашка показывает ход

- [x] Пока шаг ведут или проверки ждут, текст причины на плашке остаётся. Прячется только отдельная отметка повода, как уже написано в спеке доски.
- [x] Если у плашки нет ни верха, ни низа, и этот цикл сейчас в ходе, низ — имя действия (`restore-baseline`, `create-initial-specs`). То же для любой станции без фазовой строки, не только `specifying`.
- [x] Когда текст уже есть (ask, число вопросов, причина), ход его не подменяет. Ход в шапке остаётся.
- [x] Сценарий в `board` и проверка в `window.test.ts` / `page.test.ts`.

### Задача 3. «Принять» у Specify ждёт дельту

- [x] `reviewReady` для `specified` истинен, когда в изменении есть хотя бы одно требование. Пустой каталог и baseline в `openspec/specs/` кнопку не включают.
- [x] Plan и Design не ослабляются.
- [x] Сценарий `Accepting the spec adds specified` требует дельту. Новый сценарий: дельты нет — на месте ворот пусто, ни кнопки принятия, ни ворот `specifying`.
- [x] Поправить тест, который сейчас ждёт кнопку без файла.

Файлы: `src/window/page.ts`, `src/window/page.test.ts`, `openspec/specs/sidebar/spec.md`.

### Задача 4. Успех принятия не висит над доской

- [x] `'Принято.'` и `'Комментарий записан в ревью.'` не попадают в `view.status`.
- [x] Ошибка (`Принять не удалось.`, пустой комментарий) остаётся в этом месте, пока следующий жест её не сменит. После отдачи документа поле сбрасывается, чтобы обновление страницы не хранило старую ошибку вечно.
- [x] Сценарий принятия плана больше не ищет текст «Принято» между шапкой и доской. Метка на цикле — доказательство.

### Задача 5. Снимок

- [x] `snapshot(surface, view)` собирает то, из чего `boardDocument` уже рисует шапку, ряды и спину.
- [x] Поколение растёт на смене хода, на `refresh` и на успешном `POST`.
- [x] `GET /snapshot` отдаёт JSON. HTML по `GET /` не меняется.
- [x] Тесты снимка на ход, пустую плашку с действием и отсутствие кнопки Specify без дельты.

### Задача 6. React-клиент вместо строкового документа

- [ ] Зависимости `react` и `react-dom`, JSX, esbuild-бандл при старте board.
- [ ] Клиент рисует шапку, доску, сайдбар и настройки из снимка. Черновики строк и выбранный ряд спины — состояние клиента.
- [ ] SSE `GET /events`. Клик принимает ответ-снимок и не ждёт опроса трекера.
- [ ] Смена станции сама открывает её слой. Смена текста спеки при той же станции не закрывает ряд, который человек читает.
- [ ] Перенести сценарии `page.test.ts` на снимок и `react-dom/server`. Удалить сборку HTML-строк и встроенный скрипт.
- [ ] Сценарий «страница читает трекер, пока открыта» дополняется: открытый клиент получает новое поколение без перезагрузки.

### Задача 7. Попап хода

- [ ] Новый запуск агента обрезает свой лог, а не дописывает прошлый.
- [ ] `projectLog` оставляет реплики, старт инструмента (имя и короткий путь или первая команда) и провал. Thinking, `system` и `user` выкидывает. Хвост — 80 строк.
- [ ] Pill в шапке открывает попап, пока ход есть. Попап перечитывает проекцию раз в секунду и закрывается крестом.
- [ ] Без хода pill нет.

### Задача 8. Промпт не отправляет агента в бандл

- [ ] В `prompts/sdd.md` одна фраза: глаголы только из `CONTEXT.md`; `sdd.mjs`, `bin/` и `node_modules` не искать и не читать.
- [ ] `src/machine/skill.test.ts` по-прежнему проверяет, что шаг не пересказывает процедуру.
- [ ] Это не ужимает thinking модели. Это убирает поиск harness, который в логах specify съел сотни килобайт.
