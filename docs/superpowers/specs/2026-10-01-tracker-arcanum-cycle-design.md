# Цикл в Трекере, Аркануме и arc

Машина, скиллы и рантайм не меняются. Они по-прежнему видят метки `sdd:*`, ключ тикета и ветку `sdd/<ключ>`. Под портами `Tracker`, `Review` и `Vcs` появляются три адаптера. Грамматика меток остаётся над швом.

Очередь — настройка адаптера, та же роль, что метка очереди на GitHub. Тип тикета цикла — `typicalTask`. Его воркфлоу — [AI SDLC](https://st.yandex-team.ru/admin/queue/LAVKAOPSCORE/workflows/edit/W69886) (`W69886`). Рантайм, скиллы, политика машины и граф воркфлоу не входят в эту работу. Флаг авто-слияния ревью адаптер не меняет.

## Идентичность

Ключ цикла — ключ тикета Трекера. Ревью Арканума принадлежит тикету, когда в поле задач ревью стоит этот ключ. Ветка — `sdd/<ключ>`, например `sdd/LAVKAOPSCORE-133`. Несколько открытых ревью на один тикет останавливают машину.

Parent и Depends читаются из связей тикета.

## Что адаптер показывает машине

`listOpen` отдаёт тикеты типа `typicalTask` в настроенной очереди. В `labels` адаптер дописывает `sdd:cycle` и метку очереди, чтобы фильтр машины их сохранил. Обратно в Трекер эти две метки не пишутся: их задают тип и очередь.

Статус воркфлоу читается как одна метка фазы:

| Фаза | Статус |
|---|---|
| — | `open` |
| `proposing` | `proposal` |
| `proposed` | `solutionProposed` |
| `specifying` | `requirementsGathering` |
| `specified` | `specification` |
| `designing` | `design` |
| `designed` | `theDesignIsConsistent` |
| `tasking` | `decomposition` |
| `implementing` | `development` |
| `verifying` | `check` |
| `accepting` | `needAcceptance` |
| `accepted` | `confirmed` |
| — | `closed` |
| `cancelled` | `cancelled` |

Статуса нет в таблице — чтение бросает исключение. Адаптер не подставляет `proposing`. Тикет другого типа в `listOpen` не попадает.

Теги `sdd:auto-plan`, `sdd:auto-spec`, `sdd:auto-design`, `sdd:auto-merge`, `sdd:auto-review` и `sdd:wait-human` проходят как есть. Переход по ним не выбирается: машина уже запросила целевую фазу.

Переход `open` → `proposal` в воркфлоу показывает экран с необязательным тегом по умолчанию `sdd:auto-spec`. Адаптер этот тег не снимает.

## Запись фазы

`editLabels` переводит пару фаз в переходы воркфлоу. Робот нажимает:

| Было | Стало | Переходы |
|---|---|---|
| `open` | `proposing` | Предложение |
| `proposing` | `specifying` | Предложить, затем Согласовано |
| `proposed` | `specifying` | Согласовано |
| `specifying` | `designing` | Согласовать, затем Согласовано |
| `specified` | `designing` | Согласовано |
| `designing` | `tasking` | Согласовать, затем Декомпозировать |
| `designed` | `tasking` | Декомпозировать |
| `tasking` | `implementing` | Реализовать |
| `implementing` | `verifying` | Проверить |
| `verifying` | `accepting` | Ждем подтверждения |
| `accepting` | `accepted` | Подтвердить |

`tracker.close()` после перехода в `accepted` нажимает «Закрыть».

Человек проходит гейт кнопкой Трекера. `phaseHint` называет её: из `proposing` — «Предложить», из `specifying` и `designing` — «Согласовать». Следующий опрос видит статус гейта и берёт строку таблицы с одной дугой.

Откат идёт кратчайшим путём по рёбрам, которые в воркфлоу уже есть: «Уточнить предложение», «Уточнить требования», «Уточнить дизайн», «Исправить», «Декомпозиция». Новых рёбер адаптер не добавляет. Пути нет — исключение, статус не меняется.

Два перехода одного вызова идут по порядку. Второй не прошёл — тикет остаётся на статусе гейта, следующий опрос читает эту фазу.

## Арканум

Порт `Review`. Номер ревью машина по-прежнему передаёт строкой.

`pulls(key)` возвращает ревью, в поле задач которых стоит ключ тикета. Открытое — `OPEN`, влитое — `MERGED`. `ensurePull` возвращает единственное открытое. Его нет — ревью открывается на ветке `sdd/<ключ>` с этим тикетом в поле задач. Заголовок берётся из аргумента вызова и для поиска не используется.

Тред — замечание ревью, включая вложенные. Закрытое замечание — разрешённый тред. `path` и `line` есть, когда замечание стоит на строке диффа. `resolveThread` закрывает замечание. `reply` отвечает в его последний комментарий.

Разговор — комментарии ревью без файла, по порядку. Описание ревью в разговор не входит. Метка робота и игнор-лист `sandcastle.yaml` читаются как сейчас.

В расчёт чеков идут обязательные проверки. Есть упавшая — `red`, есть ещё идущая — `pending`, все прошли — `green`, обязательных нет — `none`. Влитое ревью — `green`. Проверки не прочитались — исключение, не `green`. `checksText` отдаёт имена проверок и текст упавших логов.

`flag`: замечание с файлом становится открытым тредом на этой строке. Замечание без файла остаётся комментарием разговора.

`merge` вливает ревью в базовую ветку до возврата из вызова. Уже влитое — успех. После вызова ревью не `MERGED` — исключение. Голос `ship` этот вызов не ставит. Машина зовёт `merge` только при теге `sdd:auto-merge` и зелёных чеках, затем в том же ходе читает тикет снова. Флаг `on_satisfied_requirements` оставляет ревью открытым до решения Арканума, поэтому адаптер его не включает и не снимает.

`range`: `head` — коммит головы ревью, `base` — база, в которую его вливают.

## arc

Порт `Vcs`. Имя ветки берётся из префикса настройки: `sdd/<ключ>`. База — базовая ветка этого запуска. Корень адаптера — монтирование сервиса.

Ветка заводится один раз. Её нет ни локально, ни на сервере — она отрезается от базы. Повторный заход её не пересоздаёт.

`push` публикует `sdd/<ключ>` и ставит upstream. Ревью этот вызов не открывает. Неудачный `push` до `ensurePull` не доходит.

`published` истинно, когда коммит совпадает с концом ветки на сервере или является его предком. Чужой ключ и неопубликованный коммит дают ложь.

`compare` возвращает коммиты `base..head` и трёхточечный дифф. Нет такого коммита — `null`.

`dirty` перечисляет пути, которые `arc status` показывает изменёнными. Чистое дерево — пустой список. Грязное дерево останавливает публикацию до `push`.

Worktree цикла лежит в настроенном каталоге worktree. Имя каталога — ветка, где `/` заменён на `-`. Он создаётся на `sdd/<ключ>` и при повторном заходе используется снова. Грязное дерево вперёд не перематывается. `filesAt` читает файлы этой ветки.

## Сбои

Адаптер не превращает ошибку в `sdd:wait-human`. Опрос падает с исключением. Тикет остаётся на последнем успешном переходе.

## Тесты

Таблица переходов — чистая функция, без сети. Покрыты каждая строка таблицы записи, пропуск гейта двумя переходами и откат коротким путём по существующим рёбрам. Отдельно: неизвестный статус падает, `merge` оставляет ревью открытым и падает, `published` ложен для чужого ключа и для неопубликованного коммита. Тесты машины остаются на памяти портов.
